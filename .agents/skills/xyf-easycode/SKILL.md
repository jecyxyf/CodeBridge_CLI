# XYF EasyCode

本技能负责两件事：技能路由、总工作流程。具体操作方法由各子技能负责。

## 1. 技能路由

下列目录均相对于本文件所在的 xyf-easycode 根目录。进入某个阶段时，读取对应的 SKILL.md 并执行；只读取当前任务需要的说明。Agent 分工、操作方法和检查要求沿用对应子技能的规则。

| 子技能 | 作用 | 目录 |
|---|---|---|
| [brainstorming](subskills/brainstorming/SKILL.md) | 通过对话梳理并确认需求与设计 | subskills/brainstorming/ |
| [xyf-archify](subskills/xyf-archify/SKILL.md) | 从需求或源码生成、维护架构，部署可编辑网页；处理指定架构修改、名称翻译和数据取回 | subskills/xyf-archify/ |
| [xyf-code](subskills/xyf-code/SKILL.md) | 按已确认架构组织编码、测试和集成 | subskills/xyf-code/ |
| [xyf-archifycheck](subskills/xyf-archifycheck/SKILL.md) | 只读核对代码是否符合架构或指定文档，报告差异和证据 | subskills/xyf-archifycheck/ |
| [review-agent](subskills/review-agent/SKILL.md) | 只读审查代码改动新引入的缺陷，按 P0～P3 分级报告 | subskills/review-agent/ |

## 2. 总工作流程

### 判断从哪一步开始、到哪一步结束

先从用户输入和已有上下文确定目标项目、交付目标、工作范围及已有授权。用户未指定项目时使用当前工作项目，并读取其协作规则。用简短表格说明本次执行的起点、终点和依据；能够确定时直接继续，只询问缺少的关键信息。

核对已有需求、架构和代码是否满足后续步骤的前提，不能仅因文件存在就认为前一步已经完成。已有且仍适用的确认结论直接沿用。前提不满足时，指出缺项并补齐必要步骤；需要扩大工作范围或写入授权时，先取得确认。

完整开发任务从确定的起点顺序执行到第 5 步；单项任务在完成用户指定范围后结束。用户明确指定步骤或结束位置时优先遵守，不把只读检查扩展为编码，也不把架构维护扩展为业务实现。

### 五步主流程

| 步骤 | 工作 | 调用子技能 | 交给后续步骤的结果 |
|---|---|---|---|
| 1 | 梳理并确认需求与设计 | brainstorming | 已确认的目标、范围和设计结论 |
| 2 | 生成或维护架构，部署架构网页 | xyf-archify | 已核对的项目架构、实际文件路径和网页交付结果 |
| 3 | 按架构编码、测试与集成 | xyf-code | 实际代码改动、测试结果和明确的审查范围 |
| 4 | 核对代码是否符合文档 | xyf-archifycheck | 逐项核对结果、差异证据及无法确认项 |
| 5 | 审查代码改动中的缺陷 | review-agent | 缺陷清单、严重程度及整体审查结论 |

第 1 步的需求与架构设计讨论按 xyf-archify 的既有约定使用 brainstorming。确认后的结论传给第 2 步，由 xyf-archify 写入架构；不要在第 2 步重新进行相同讨论。

| 用户输入与已有产物 | 起点与后续流程 |
|---|---|
| 从新需求完成整个项目，需求尚未确认 | 1 → 2 → 3 → 4 → 5 |
| 需求已确认，尚无可用于实现的架构，要求继续开发 | 2 → 3 → 4 → 5 |
| 已有有效架构，要求按架构实现 | 3 → 4 → 5 |
| 代码已完成，要求核对并审查实现 | 4 → 5 |
| 只生成、维护架构或部署架构网站 | 第 2 步完成后结束；需求未明确时先做第 1 步 |
| 只检查代码是否符合文档 | 第 4 步完成后结束 |
| 只审查未提交改动、分支差异或指定提交的缺陷 | 第 5 步完成后结束 |
| 明确指定步骤继续或只做某阶段 | 校验前提后，从指定步骤执行到用户要求的终点 |

### 阶段衔接与返工

- 每次调用子技能，传入实际项目路径、架构或文档路径、模块或文件范围、已有确认与授权，以及上一阶段核对过的产物。架构默认位置为目标项目的 docs/archfiy/archify.json；用户指定路径和项目已有的实际配置优先，不能拿技能工具的空框架代替项目数据。
- 第 3 步需要的架构路径和实现范围确认按 xyf-code 执行，沿用本次已有的有效确认。记录代码审查目标是未提交改动、基准分支差异还是指定提交，并交给第 5 步；只读审查不因此自动获得修复权限。
- 第 4、5 步发现问题时，已经授权编码的任务返回第 3 步，在原范围内修复并测试，再重新完成受影响的文档核对和缺陷审查。只读任务报告问题后结束，不修改代码或文档。
- 问题涉及需求或架构方案变更时，说明原因和影响，取得用户确认后返回第 1 或第 2 步；不能通过修改文档来掩盖实现偏差。架构或代码变化后，受影响的旧检查结论失效。
- 前置条件、环境或关键信息不足时，暂停受影响步骤，继续能够独立完成的部分并报告阻碍。反复无进展时说明原因，不把未完成步骤写成通过。

### 流程结束与交付

用简短表格报告实际执行的起止步骤、各阶段结果、产物位置、已运行的检查和待处理问题。架构网页的生成、访问、保存与页面检查要求由 xyf-archify 负责；未运行的测试、未完成的核对及未处理的缺陷如实列出。

完整流程只有在范围内的实现、测试、文档核对和缺陷处理均完成后，才能报告完成；单项检查则报告检查是否结束及其发现，不把发现问题等同于已修复。提交、推送和合并只按用户明确要求执行。
