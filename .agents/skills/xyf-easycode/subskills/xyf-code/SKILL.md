# XYF Code

主代理担任监工，组织子代理按模块编码、测试和返工，逐模块审查并负责整体集成。严格按已确认的架构方案实现，不能自行删减、替换、简化或改变方案。

## 1. 确定依据和范围

确定目标项目、实现范围和架构配置。优先使用用户指定或 xyf-archify 交付的路径；默认使用目标项目 `docs/archfiy/archify.json`，旧项目实际使用 `docs/archify/archify.json` 时沿用；两处都有数据且基准不明时先解决。不能把工具自带空框架当作业务需求。开始编码前，向用户明确实际配置的绝对路径并请求确认，只有确认后才继续；明确本次实现全部模块还是指定模块或方法。

读取项目协作规则、现有源码和构建配置；以源码为已有实现基准，以当前已保存的架构为本次需求。先使用共享工具 [model.js](../../tools/html/assets/model.js) 的 `EasyCode.Model.validate` 检查数据错误和本次相关警告，字段说明见 [完整模板](../../tools/html/templates/archifytemplate.template.jsonc)。架构为空或关键设计不清、输入输出未确认或实现所需信息缺失时，暂停相关模块并向用户确认，不能猜测；用户确认的信息可作为本次依据，但不得因此擅自回写架构。

| 架构内容 | 实现依据 |
|---|---|
| groups、groupId、englishName | 所属层级；代码根目录下使用层级英文名作为目录，不强制语言命名空间 |
| repository、language、codeLocation | 代码根目录、语言、相对代码位置 |
| purpose、requirements、dependencies | 模块功能、需求与依赖项；每个依赖项是文字，不能据不清楚的内容猜测 |
| parameters、structures、interfaces、events | 公开参数、数据结构、方法、事件及其类型、默认值、输入输出、流程和错误处理 |
| tests | 模块需验证的步骤与预期，不代表测试已通过 |
| relations | 用户的画布标注，不用于决定或审查代码依赖 |

按稳定 ID 定位模块；检查分层、公开英文名和依赖接口。路径缺失时沿用现有结构；分层或公开英文名缺失、无效或冲突，已有结构冲突，或依赖无法判断时向用户确认，不自行命名公开接口或迁移代码。写入路径必须在目标项目授权范围内，不能写入技能 tools/ 或其他项目。

更新已有代码时，对照当前配置与源码，必要时使用可信旧配置及源码调用查找受影响的模块和调用方；不猜测历史改动。执行中配置发生变化时，暂停受影响任务并重新核对，之前对受影响模块的通过结果失效。

## 2. 分工、实现与审查

监工按模块需求、`dependencies`、公开接口和已有代码中的实际依赖安排开发、测试、审查及集成顺序；独立模块可并行，依赖未满足的模块按顺序执行。监工保证同一时间一个模块只有一个代理修改，一个子代理一次负责一个模块；更换负责人前确认原负责人已停止并交接上下文。共享文件由监工处理或安排串行修改，保留已有用户改动。多代理不可用或被上级规则禁止时说明阻碍，不冒充已完成多代理开发。

| 阶段 | 工作 |
|---|---|
| 分配 | 监工给子代理模块 ID、当前模块说明、依赖、文件范围、验收要求和授权，并记录配置版本或哈希 |
| 开发 | 子代理实现模块并运行相应测试，报告改动、测试结果和问题；完成报告触发监工审查，不假设有 Hook |
| 审查与返工 | 监工以 `archify.json` 中该模块的说明为依据，逐项核对功能需求、依赖、公开接口、输入输出、流程、错误处理和测试结果；审查时只读。未通过时反馈具体问题，由负责人修改并再次审查 |
| 通过与集成 | 模块通过前代理空闲等待，可用后续任务唤醒；监工只在内部记录完成，不写入文档或架构。所有模块通过后由监工进行整体集成与检查 |

更换负责人时遵守单模块单负责人规则；无法确认原代理已停止修改时暂停该模块。依赖、环境或测试无法满足时说明阻碍，不把模块标为完成；反复无进展时停止无效返工。优先复用项目测试工具，按架构 `tests` 执行；没有测试项时根据模块需求验证实际功能，并运行必要的构建和类型检查。整体集成与单模块审查分别报告。

公开方法、参数、字段和事件遵守配置中的 `englishName`、类型、默认值和行为；内部方法、接口和变量可自行创建，但不能改变公开接口或偏离方案。方法和事件的 `flow` 不为空时逐步实现，并在每步前添加目标语言有效的编号注释，如 `步骤1`；为空时可自行确定步骤，仍须添加编号注释并满足需求。复用现有库和项目惯例，不为事件另建消息服务，不以空实现、固定返回值或伪造结果冒充完成。

发现方案无法实现时，立即停止受影响工作，向用户说明障碍与影响并推荐新方案；只有用户明确确定新方案后才能继续。除此以外，不得因实现方便、既有代码不同或测试通过而偏离方案。

## 3. 架构回写与交付

默认禁止回写 `archify.json`，包括代码位置、来源、状态和版本；主代理、子代理和其他技能均不能绕过。唯一例外是执行中发现模块按当前方案无法实现，监工说明问题、推荐新方案并明确回写范围后，用户明确确定该新方案。只按确认范围回写，保留其他内容及稳定 ID，不顺带修改其他字段。

获准回写时，使用 [project-file.js](../../tools/html/assets/project-file.js) 的 `EasyCode.ProjectFile.parse` / `stringify` 或相同规则处理 纯 JSON 对象格式，不执行文件；模型语义更新使用 `EasyCode.Model`。写前记录并再次核对原文件内容或哈希，有变化时处理冲突；写后解析、校验并深度比较。可选使用现有 Node 的 [files.mjs](../../tools/html/scripts/files.mjs)，不为此安装 Node。`verified` 表示有源码依据，不表示业务测试通过。

用简短表格报告已实现范围、改动文件、模块和整体检查结果及未完成事项；不能把未执行的测试写成通过。提交、推送和合并按用户要求执行，不自动发布。
