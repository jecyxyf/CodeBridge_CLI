# 安全边界与验证记录

## 当前保证与非保证

- 仅出站 SSH；显式配置代理失败不自动直连。SOCKS5 代理远程解析目标域名，HTTP 代理使用 CONNECT。
- SSH 仅密码认证，不查找 SSH 私钥或 agent。服务器指纹核对发生在密码发送之前。密码只存在进程内存，不保存、不放 argv、不记录日志；Python 不能保证内存字节的安全擦除。
- 本地 HTTP 控制面仅绑定 127.0.0.1，状态和动作 API 都需要随机临时令牌，并检查 Host/Origin。没有 CORS 放行。聊天界面不是远端网页服务。
- 不改变 SSH、防火墙、系统安全策略；不使用 allow_other。远端用户本身必须有挂载权限。
- rclone 默认忽略共享根目录内的符号链接/Windows junction，导出根路径及其父路径不能是符号链接/重解析点。隔离配置、清除环境覆盖，并关闭 copy-links、links、vfs-links。
- **不是硬沙箱**：恶意本地程序在检查和访问之间替换目录/链接，或预先存在的硬链接，仍可能越过用户期望的目录边界。只适用于用户信任的本地目录和本地程序。若要求对不可信本地写入者进行 race-resistant confinement，需要平台原生沙箱或另行设计的文件服务，不能由预扫描实现。
- 远端密码认证账户和同账户进程被视为有权读取此共享内容。

## 写入与断开

VFS `writes` 模式已验证单独读取、写入、随机覆盖和重命名；未认证所有编辑器保存策略。`--vfs-write-back 0s` 尽快写回，但不代表同步落盘。正常操作应先保存并关闭远端文件，确认本地文件已更新，再断开。强制断开可能留下缓存未写回数据。缓存保存在 `~/.codebridge/cache/<session>/`，不会自动删除。不要将缓存目录直接覆盖到工程目录；应按原文件核对恢复。

断开当前以关闭 SSH 通道结束前台 SSHFS，再等待本地服务退出；不是已验证的持久化屏障。本版本不适用于以断开动作作为安全提交保证的工作流。远端繁忙挂载可能需用户手动卸载，程序不会擅自使用强制/懒卸载掩盖问题。

## 实际验证环境

云端 Linux，Python 3.12，Paramiko 3.5.1，rclone 1.75.2。没有 `/dev/fuse`，未安装/运行真实 SSHFS 挂载。没有 Windows/macOS 桌面或用户服务器凭据。没有修改任何用户机器或系统 SSH/防火墙设置。

已执行 39 项自动化测试，全数通过。涵盖：

- 二进制管道 1 MiB 全字节值传输。
- SSH 指纹不匹配时不会发送密码。
- 代理失败不会调用直接 TCP fallback；拒绝未支持的代理凭据。
- 旧 rclone 拒绝启动；根目录链接拒绝。
- HTTP API 缺失令牌、跨来源请求拒绝，合法状态读取成功。
- 设置保存不含 SSH 密码，代理凭据在保存前被拒绝。
- 数据通道没有空闲 30 秒超时；SSH 健康检查每 15 秒发起，等待响应最多 10 秒。
- rclone 真实 stdio SFTP：创建/删除目录与文件，256 KiB 二进制内容、随机覆盖写、重命名、本地变更可见。
- `..` 路径遍历与静态符号链接不暴露共享目录外文件。

未验证，不能据此宣称完成：

- Linux SSHFS 的实际 FUSE 挂载、读写、断网、重连、繁忙卸载和长时间编辑器工作负载。
- Windows 客户端安装/代理/原生管道和浏览器启动。
- Windows SSHFS-Win 被动管道、OpenSSH 非交互会话盘符可见性与清理。
- macOS 安装、驱动审批/重启、SSHFS 兼容性。
- VFS 强制断开、断电和高并发时零数据丢失。
- 恶意本地链接替换竞态/硬链接隔离。

## 新增诊断的含义

- “SSH Ping”只连接指定 SSH 端口并读取 SSH 服务标识，不发送密码、不进行 ICMP。配置代理时完全沿用代理，没有直连补测；失败也不证明主机离线。
- “测试代理”建立到所选服务器 SSH 端口的真实 SOCKS5/HTTP CONNECT 隧道，并收到 SSH 标识才通过。只打开本地代理端口不算成功。HTTP CONNECT 解析保留与响应头合并到同一数据包的 SSH 字节。诊断子进程最长 30 秒，包含 DNS 解析的外层超时。
- 连接阶段区分 SSH 连接、身份验证、挂载中、系统确认挂载、目录可读、读写已验证。服务可达不等于密码正确，密码正确不等于挂载成功。
- “验证读写”显式在选定目录独占创建随机 `.codebridge-probe-<uuid>` 文件，远端通过挂载读出特定内容，再用独立写句柄更新它。本地确认真实文件写回后才通过，并仅删除本次已核对内容的临时文件。不修改工程已有文件。
- 远端操作超时、连接改变、内容异常或清理失败时不会报告完整成功。若远端结果不确定，为避免与未完成写回竞争，会保留该临时文件并显示路径，供连接停止后核对清理。读写验证不是断电持久化保证。
- 已增加 HTTP 合并响应回归、代理拒绝不回退、读写临时文件保护、远端列表超时、旧会话结果丢弃、命令确认看门狗及本地写回/inode 替换测试。

## 已知 O_RDWR 兼容性问题

实际 rclone 1.75.2 stdio SFTP 测试发现：已有本地文件以 `r` 打开读取成功；以 `r+` 打开后读取返回 `SFTPError: Expected data`。切换 full 缓存也不能消除此问题。单独读取后单独写入、随机覆盖写和重命名的测试通过。新增诊断采用分开的读/写句柄，是对这些基本能力的验证，不应被解释为所有 POSIX 文件操作正常。真实 SSHFS、编辑器、构建工具是否使用受影响的组合需要进一步实机验证；在此之前不建议用于重要项目。

## 实机验收步骤

1. 在无敏感内容的专用空目录建立测试文件，运行双方部署脚本和远端 `codebridge-mount --self-test`（仅检查依赖，不等同真实挂载）。
2. 核对服务器指纹，输入代理和密码，连接；仅在显示远端挂载路径后继续。
3. 在远端该路径创建文本、二进制文件、子目录；在本地验证内容；远端原位修改、重命名、删除后再核对。
4. 本地修改其他文件，等待至少 1 秒，在远端重新打开检查。不要同时写同一文件。
5. 保存并关闭所有文件，确认本地内容正确，断开；远端确认挂载释放，重连得到新会话路径。
6. 在仅测试数据上模拟网络失败，验证 UI 退出已连接状态、无假挂载成功，并检查缓存和实际文件。
