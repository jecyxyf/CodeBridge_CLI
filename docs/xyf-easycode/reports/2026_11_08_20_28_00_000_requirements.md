# CodeBridge 需求变更记录：最终编译产物严格唯一性与无外露依赖

## 1. 变更背景与范围

- **项目**: CodeBridge CLI (`0.0.1`)
- **记录标识**: `2026_11_08_20_28_00_000_requirements`
- **架构文件**: `docs/xyf-easycode/html/software_architecture.js`
- **核心变更**: 确立最终编译输出产物的绝对纯净性约束。最终编译交付产物**严格只能有且仅有 `CodeBridgeLocal` 与 `CodeBridgeVPS` 两个独立可执行程序**，严禁在最终交付目录中残留、外露任何其他可执行程序（如原生 `mutagen` 或 `agent` 二进制）；构建期所需的中间内嵌原料必须收敛至构建缓存中，不得作为交付物暴露。

## 2. 需求调整清单

| 需求项 | 原始定义 | 调整后约定 | 涉及模块 |
|---|---|---|---|
| **交付产物唯一性约束** | 仅定义了单文件交付，未严格禁止构建目录外露中间编译的可执行文件 | 确立绝对铁律：编译交付结果严格仅保留 `CodeBridgeLocal` 与 `CodeBridgeVPS` 两个可执行文件，交付目录中严禁外露任何辅助程序或第三方可执行文件 | 全局描述（`description`）及两端主程序 |
| **构建原料隔离与收尾** | 编译时生成的 Mutagen 原生组件存放在 `bin/embedded/` 中外露 | 明确要求构建流水线对中间临时资源进行隐藏与隔离处理，交付目录（`bin/Local/` 和 `bin/VPS/`）保持纯净，无其他可执行程序 | 构建流程规约及两端部署要求 |
| **纯净性自动化验收** | 仅对业务功能与单文件运行进行断言 | 新增“编译产物纯净性验收”测试约定（`BinaryPurityVerification`），自动扫描产物目录，断言除这两个程序外无任何多余二进制 | `module-codebridge-local`、`module-codebridge-vps` |

## 3. 架构校验结论

- **格式校验**: 严格通过严格 JSON 解析与校验，无语法错误。
- **布局锁定**: 保持原有 6 个模块、5 个分组、2 条连线；所有坐标、样式、视角、既有 ID 均完全未变。
