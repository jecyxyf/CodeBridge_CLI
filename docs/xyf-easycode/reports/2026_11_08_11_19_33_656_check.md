## 3. 本轮架构修订边界

| 内容 | 修订后的约定 |
|---|---|
| 用户交付 | Local 只拷贝 CodeBridgeLocal，VPS 只拷贝 CodeBridgeVPS；程序需匹配系统与 CPU 架构。所需组件由构建提前打包和运行时自动准备，不让用户单独安装 Go 或 Mutagen。 |
| 依赖 | 不改 Mutagen 源码，以仓库锁定提交构建匹配主程序和 Agent 包。新拉取的其他版本产物不能直接当成交付基线。 |
| Local | 参数输入、历史配置、约定默认值按顺序合并；真实调用同步与转发，保存真实会话编号；成功后保存完整生效参数。 |
| VPS | 管理资源台账、查询和服务生命周期；不能把原生 Agent 当作多主机资源登记服务器。 |
| 原生 Agent | 由 Local 的 Mutagen 经 SSH 自动安装到 VPS 磁盘并按模式启动；不再宣称纯内存运行或退出后零文件残留。 |
| 进程和连接 | 单文件不等于单进程。唯一物理连接仍是用户要求，保留为待验证阻塞项，不擅自放宽为多连接。 |
| 输出 | CodeBridge 对外统一 JSON；原生 Mutagen 仅已确认支持模板的查询使用 JSON，Agent stdio 仍是二进制协议。 |
| 日志 | Logger 保留四个方法。各自程序目录保存 `logs/yyyy_mm_dd.log`，保留 90 天；业务模块负责采集底层日志，不能将短时 CLI stderr 当作完整后台日志。 |
| 停止 | 只停止本程序登记且已确认归属的资源；停止不明则保留绑定，不清空台账，不影响其他程序。 |
| 图与接口 | 保留 6 个模块、5 个分组、2 条连线；现有 ID、方法名、参数名称/类型/必填与默认值、结构体字段、坐标、样式、视角及连线端口均不改变。只修正文字、证据、状态、待验证项与测试约定。 |

这些是设计约定，不是本轮已实现的功能。
