# EasyCode Archify 初版设计

日期：2026-10-23

状态：用户已于 2026-10-23 确认并授权执行；实现进度见同目录体系下的实施计划。后续修改继续更新本文件。

## 1. 要做什么

做一个可以编辑的软件模块画布。Agent 负责讨论方案、阅读代码和整理模块；用户在网页中查看、修改并保存。最终交付一个自带样式、脚本和项目数据的 HTML，使用时无需安装 Python、Node.js，无需启动服务或联网。

这不是直接复制 archify。沿用它依据实际代码查证模块和关系的做法，在现有 `easycode/subskills/easycode-archify/` 中建设专用编辑器。继续使用仓库现有目录名，不在本次工作中重命名整个项目。

### 用户已经明确的需求

| 方面 | 要求 |
|---|---|
| 开发前 | 聊清方案，整理成模块和接口，最终用文档指导 Agent 开发 |
| 调整功能 | 修改网页中的方案，更新文档，再指导 Agent 修改代码 |
| 分析外部工程 | 从实际代码还原模块、软件分层、接口和关系 |
| 画布 | 类似 ComfyUI 的大画布，可以移动视野、缩放、摆放节点 |
| 节点 | 一个节点代表一个模块，用户可以自由添加和编辑 |
| 分组 | 多个模块组成一个组，表示软件的一层 |
| 节点内容 | 模块用途、对外接口、各接口用途、输入参数、输出参数 |
| 模板 | 网页的大模板与模块节点的小模板独立维护 |
| 保存 | 默认覆盖当前文件，另存为才产生副本，不自动生成版本副本 |
| 文档功能 | 模块文档模板和一键更新按钮留到后续阶段 |

### 本设计补充的初版选择

以下是为实现初版选定的默认做法，用户可以在审阅时调整：

- 覆盖保存以桌面版 Chrome、Edge 为目标浏览器。
- 分组先做一层；一个模块最多属于一个组，也可以不分组。
- 模块之间用带方向的连线标记关系，不区分调用或依赖，不做接口插口之间的连线。
- 节点只显示只读摘要，点击编辑按钮打开独立窗口；完整内容在窗口内分区编辑。
- 初版使用简体中文界面和深色画布，不增加主题选择器。
- 一个项目对应一个可编辑 HTML；编辑的数据内嵌在 HTML 中，不要求用户维护额外 JSON 文件。

## 2. 第一阶段范围

| 包含 | 完成标准 |
|---|---|
| 画布模板 | 工具栏、画布、保存状态、缩放和适应视野 |
| 节点模板 | 名称、职责摘要、接口数量、状态和编辑入口 |
| 模块编辑 | 添加、重命名、编辑、删除、拖动节点 |
| 分组 | 创建、命名、加入或移出模块、移动整组、解散组 |
| 模块关系 | 拖拽创建有方向的连线，点击后高亮橙色，通过中间图标编辑文字或删除 |
| 保存与另存为 | 修改保存回同一 HTML；明确选择另存为时才建立副本 |
| 基本检查 | 发现重复标识、无效关系、关键字段缺失，明确指出位置 |
| 技能说明 | 规定新方案、修改方案、代码分析三种用法，以及代码依据规则 |
| 示例 | 一个可编辑的小型软件方案，完整演示以上能力 |

本阶段不实现 Markdown 模板、批量更新模块文档、网页调用模型、网页直接修改项目代码、多人协作、云端账号、流程执行、分组嵌套和与 ComfyUI 的文件兼容。后续文档功能不以无效按钮占位。

三种使用场景在初版中先统一落到“可编辑、可保存的模块方案”。让 Agent 按生成文档实施、核对验收的完整流程，在文档阶段补齐。

## 3. 页面与节点

### 3.1 画布大模板

工具栏提供项目名称、添加模块、创建分组、适应视野、保存、另存为以及保存状态。画布显示背景网格、分组、模块和连线。

- 拖动空白画布移动视野；滚轮围绕指针位置缩放，设置合理的最小和最大比例。
- 拖动模块标题移动节点；编辑按钮、正文选中文字和编辑窗口中的操作不触发画布拖动。
- 进入初始页面时显示完整示例或当前项目，避免节点在视野之外。
- 分组是带名称的区域，不是代码目录的自动映射。分组表示用户选定的软件分层。
- 节点归组通过明确的选择操作完成，不因拖动越过边界而悄悄改变归属。
- 组的范围包住成员节点；拖动组标题同步移动成员节点及其连线。
- 解散组保留其中的模块与关系。删除模块会列明并一并删除与它相连的关系。
- 删除模块或关系需要一次明确确认；初版不加入完整撤销历史。

### 3.2 模块节点小模板

每个节点使用同一个模板、填入自己的数据。标题栏包含模块名称和编辑入口；底部显示内容来源状态，上下左右四边中间各有一个连接圆点。编辑窗口包含以下区块：

| 区块 | 内容 |
|---|---|
| 模块信息 | 中英文名称、职责、代码位置、所属层级；默认展开 |
| 对外接口 / 参数 | 中英文名称、类型、说明、可选默认值；默认收起并显示数量 |
| 对外接口 / 方法 | 中英文名称、用途、输入参数、返回结果、可选实现流程和错误；默认收起并显示数量 |
| 对外接口 / 消息事件 | 中英文名称、说明、发出或接收、触发条件、携带的数据；默认收起并显示数量 |
| 对外接口 / 测试项 | 测试名称、步骤、预期结果；默认收起并显示数量 |

节点只读显示名称、职责摘要、各类成员数量和状态，不展开完整内容。点击铅笔按钮打开可滚动的编辑窗口。点击组标题展开或收起，各条目以及方法的输入、返回结果、实现流程可单独折叠；新增自动展开所属组和新条目，折叠不清空填写内容、不标记数据修改。底部的确定、取消、删除按钮固定显示并保持同一种风格。编辑先写入独立草稿，点击确定才更新模块；取消或 Esc 丢弃草稿。新建模块也先打开窗口，取消不会留下空模块。删除已有模块需再次确认，并删除其关联关系。确定后通过顶部保存按钮写入 HTML；窗口打开时 Ctrl+S 提示先确定或取消。拖动、10 像素磁吸和连线继续在画布上操作。

模块、参数、方法、事件的名称统一为一行两列：左中文名、右英文名，可以先填其中一种。旧名称按原样保留，不自动翻译。旧接口以“方法”展示，保留原标识、参数、出处与核对信息。代码出处与待确认事项放入对应模块或方法的折叠区。新增字段为可选字段，打开、折叠或无修改确认不补写旧数据；代码位置缺省时显示原出处路径与起始行。

“方法”用于记录模块公开的函数、方法和 HTTP API，不强制具有 HTTP 路径或请求方法。模块参数记录公开配置或属性，方法参数放在对应方法下。事件只描述对外消息，测试项记录验收要求，不执行代码。

| 接口字段 | 规则 |
|---|---|
| 中英文名称 | 一行两列，至少填写一种；代码分析时保留实际代码名称 |
| 用途 | 必填；说明这个接口完成什么事情 |
| 输入参数 | 可添加、编辑和删除；包括中英文名称、类型、是否必填、说明和可选默认值 |
| 输出参数或结果 | 可添加、编辑和删除；包括中英文名称、类型、说明 |
| 实现流程与错误 | 选填；实现流程可单独折叠 |
| 代码出处 | 可选；按实际读取到的代码填写 |

输入与输出分别记录“已确认”或“待确认”。已确认没有输入或返回值时允许空列表，显示“无输入参数”或“无返回结果”；尚未弄清时显示“输入待确认”或“输出待确认”，不能把空白草稿说成没有参数。未知类型明确记录为“未知”，不猜测类型。不在初版加入请求调试、接口执行或自动生成客户端代码。

### 3.3 模块连线

按住模块的任意连接圆点，拖到另一个模块的连接圆点后松开，生成箭头。拖拽起点为输出，终点为输入；单击不连线。四边圆点没有固定输入输出角色，同一点可连接多个模块。拖动时高亮输出点并显示跟随鼠标的预览线，悬停到有效输入点时高亮目标。按 Esc、指针操作中断或松在空白处及同一模块时取消，不留下箭头、不改变保存状态。直接从连接圆点拖拽，顶部和模块底部均不放新增箭头按钮。

箭头统一样式，只用于标记模块关系，不区分调用或依赖，也没有配置窗口。左键点击箭头或文字后，连线与箭头头部一起高亮橙色（`#ff9f43`），不显示选中方框。线的中间下方出现编辑、删除两个图标，避开文字；图标随平移、缩放和模块移动更新位置，保持固定大小并限制在画布内。点击编辑图标原地修改文字，双击不再进入编辑；Enter 或点击别处完成，Shift+Enter 换行，Esc 放弃，中文输入法选字不会误提交。编辑时收起两个图标，结束后恢复。备注可留空，不提示缺项或显示占位文字。点击删除图标，或选中后按 Delete、Backspace，确认后删除；编辑备注时这些按键只删除文字。点击空白或在文字编辑外按 Esc 取消选中、收起图标，单纯选中不改变保存状态。键盘聚焦箭头后按 Enter 或空格选中，并聚焦编辑图标。保存前先完成当前备注编辑，关闭页面时也检查尚未提交的备注草稿。

新箭头通过可选的 `fromPort`、`toPort` 字段保存所选边，值为 `top/right/bottom/left`，不写入关系类型，不改变格式版本。旧箭头没有连接边时自动选左右边，旧类型与出处数据继续保留，更新网页不改写旧数据。模块移动、缩放或确认修改后，连线仍连接到所选圆点。初版使用 SVG 曲线，不追求自动消除全部交叉。只调整连接边属于布局变化，不改变源码核对状态。

新建关系要求目标存在、源与目标不同，不允许完全相同的重复关系。允许循环关系。模块与接口可以保存尚不完整的草稿并提示缺项；箭头备注为空有效，结构损坏不能被当作成功保存。

## 4. 内容和代码依据

方案与代码现状使用同一套字段，但区分来源：

| 状态 | 含义 |
|---|---|
| 设计中 | 拟开发的模块、接口或关系，没有声称已经存在于代码中 |
| 已按代码核对 | Agent 已阅读相应代码，并附上支持该事实的出处 |
| 修改后待核对 | 来自已核对内容，但模块职责、接口、参数或关系含义已经被手动修改 |

这些状态适用于模块、接口及关系。修改位置、折叠状态、显示颜色或分组布局不改变代码依据状态。修改与代码有关的内容时，相关项变成“修改后待核对”；修改接口内容也使模块摘要显示有待核对内容。已有代码出处保留供复查，不能继续充当修改后内容已获验证的证明。

初版技能要求 Agent：

1. 根据请求确定是讨论新方案、修改已有方案，还是分析现有代码；仅在上下文确实无法判断时询问。
2. 分析代码时阅读入口、模块实现和实际调用位置，依据职责划分模块，不把文件夹名称直接当作架构事实。
3. 为模块、接口和重要关系记录文件、代码位置和所用版本；存在未提交改动时明确说明所读来源，不混称为某个提交的代码。
4. 将不能证实的内容记为未确认事项。没有代码出处的设想不得标成“已按代码核对”。
5. 更新已有方案时保留已有标识、用户编辑和布局。遇到用户设想与实际代码不一致时标出差异，不静默覆盖设想。

浏览器的字段检查只证明数据结构可用，不证明代码描述正确。代码正确性仍需 Agent 阅读、核对。

## 5. 数据和组件边界

项目数据是唯一内容来源。画布、节点表格、保存文件以及未来的文档功能都读取同一份数据，避免分别维护互相不一致的文字。

| 数据 | 主要字段 |
|---|---|
| 项目 | 格式版本、稳定项目标识、名称、用途、代码来源信息 |
| 分组 | 稳定标识、名称、颜色 |
| 模块 | 稳定标识、中英文名称、职责、代码位置、分组标识、坐标、参数、方法、事件、测试项、出处、来源状态、未确认事项 |
| 方法 | 保留接口字段 `interfaces`；稳定标识、中英文名称、用途、输入、输出、确认状态、实现流程、错误、出处、来源状态 |
| 事件与测试项 | 事件记录中英文名称、说明、方向、触发条件和携带数据；测试项记录名称、步骤、预期结果 |
| 关系 | 稳定标识、起点、终点、可选连接边和备注；保留旧类型、出处与来源状态以兼容旧文件 |
| 视图 | 画布位置、缩放比例；保留旧版节点和接口展开字段以兼容已有文件，新窗口按默认状态展开，折叠变化不写入项目 |

标识在创建时生成，重命名不改变标识。关系引用标识而不是显示名称。临时选择、指针状态、文件写入权限不属于项目数据。

运行部分拆为以下职责，保持边界清楚：

| 部分 | 输入与输出 | 职责 |
|---|---|---|
| 数据模型与检查 | 项目数据 → 编辑后的数据或检查结果 | 管理增删改、关系引用、来源状态 |
| 画布 | 项目与视图数据 → 节点位置、分组与连线 | 平移、缩放、拖动、定位 |
| 节点呈现与编辑 | 单个模块 → 只读卡片；编辑窗口草稿 → 确认后的数据变更 | 卡片显示摘要，窗口编辑说明和接口，取消保留原数据 |
| 文件保存 | 项目数据与页面模板 → 自包含 HTML | 绑定文件、覆盖保存、另存为、读回检查 |
| 页面入口 | 内嵌项目数据 → 初始化上述部分 | 连接工具栏、状态提示和各部分 |

基本数据流：Agent 整理项目数据 → 组装器套用画布与节点模板 → HTML 内嵌项目数据 → 用户编辑更新数据模型 → 保存完整 HTML → 下次打开还原模型和视图。

组装器只负责组合模板、样式、脚本与数据，不负责推测代码结构。第一版不引入第三方前端框架、在线字体或 CDN 资源。

## 6. 保存与另存为

### 6.1 默认保存

“保存”表示覆盖同一个 HTML，不下载一个自动加序号的文件。

双击本地 HTML 并不会自动授予网页修改该文件的权限。第一次点击保存时，用户选择当前文件并允许写入；网页保留文件句柄，后续保存写回同一文件。重新打开页面或权限失效时，可能需要重新选择或允许写入。

首次绑定已有文件时，确认它是本编辑器的文件，且项目标识与当前项目相符。取消选择或拒绝授权不修改磁盘，也不清空当前编辑内容。

保存前检查数据结构，生成自包含 HTML，完成写入、关闭写入流并读回核对项目数据后才显示“已保存”。写入失败继续显示“未保存”，并说明原因；不能把发起写入等同于保存完成。

保存过程中继续发生的编辑必须保留。如果写入的是较早的快照，页面仍显示有未保存内容；连续点击保存按顺序处理，不让旧快照覆盖新快照。

文件绑定后若检测到外部修改，保留页面草稿并提示重新打开核对或另存为，不静默覆盖另一方刚写入的内容。检测用于避免丢失编辑，不创建版本副本。

### 6.2 另存为

用户主动点击“另存为”时选择新的名称或位置。写入成功后，新文件成为后续“保存”的目标；旧文件保持原样。取消或失败时仍使用原保存目标。

### 6.3 文件内容

HTML 保存项目数据、画布模板、节点模板、样式和全部交互代码。单独复制这个 HTML 后仍能查看和编辑，不需要依赖生成时的目录。

保存从可信模板和当前数据重新组装，不直接复制包含临时编辑状态的页面 DOM。项目数据作为 JSON 内嵌，正确转义脚本结束标签等特殊内容；模块文本使用文本节点呈现，不能变成可执行脚本。

状态提示区至少区分“未保存”“正在保存”“已保存”“保存失败”。当前文件名在绑定成功后显示。带未保存内容离开时使用浏览器支持的离开提醒；不承诺浏览器崩溃后的恢复，也不把浏览器缓存当成磁盘保存。

### 6.4 浏览器边界

初版针对桌面 Chrome、Edge 的本地文件访问能力开发，并以本地 `file://` 打开方式进行真实验证。首次写入涉及的文件选择和授权是浏览器要求，不需要安装后台程序。

不支持直接写文件的浏览器明确显示覆盖保存不可用，不能把普通下载伪装成覆盖保存。正式交付前必须验证本机目标浏览器下的文件选择、覆盖、另存为和重新打开；若实测不通过，需要回到本设计调整，不能悄悄增加 Python 服务或其他运行依赖。

参考：[Chrome 本地文件访问说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[MDN 安全上下文说明](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts)。

## 7. 技能包结构与改动范围

实现主要集中在 `easycode/subskills/easycode-archify/`。以下是职责划分，不要求每个表格条目只用一个源文件。

| 位置 | 职责 |
|---|---|
| `SKILL.md` | 三种使用场景、工作步骤、生成与更新规则 |
| `references/` | 模块数据规则、代码核对规则、保存说明 |
| `templates/canvas.html` | 网页大模板、工具栏与画布外壳 |
| `templates/module-node.html` | 节点小模板、模块与接口区块 |
| `assets/` | 样式及按职责拆分的浏览器脚本 |
| `scripts/` | 供 Agent 组装 HTML、检查数据与产物的辅助脚本 |
| `examples/` | 一个说明用的小型项目数据及其可编辑 HTML |
| `tests/` | 数据、保存和主要浏览器操作的验证 |

Agent 侧组装和开发验证可以使用执行环境已有的工具；用户使用生成的 HTML 时不需要这些工具。实施计划需要明确实际采用的工具和文件清单，不要求用户安装服务来使用网页。

本阶段不修改已引入的 `easycode/subskills/archify/` 引擎，不删除其已有文件。可以在技能说明中引用其中有用的代码查证规则；编辑器使用自己的模块数据格式，避免把原图形格式硬扩展成接口手册。

父级 `easycode/SKILL.md` 的完整工作流不在这次编辑器初版中扩展。独立技能先可用，后续结合文档阶段接入父级流程。

## 8. 错误处理

| 情况 | 行为 |
|---|---|
| 草稿缺少职责或接口用途 | 保留草稿，标明缺项和位置，允许保存草稿 |
| 项目标识或关系结构损坏 | 显示具体问题，阻止把损坏数据写回原文件 |
| 代码出处未知 | 记录未确认，不补造路径和调用关系 |
| 删除被关系引用的模块 | 先列明影响，经确认后一并移除对应关系 |
| 用户取消文件选择或授权 | 返回编辑，保留全部未保存内容 |
| 写入失败或文件被外部修改 | 明确显示未保存状态，保留草稿 |
| 项目数据格式版本不支持 | 给出可理解的原因，不自动覆盖文件 |
| 文本含 HTML 或脚本片段 | 按文字显示，保存后仍按文字还原 |

## 9. 如何验收

验证关注真实使用结果，不为每条样式建立重复测试。

| 验收项 | 方法与通过标准 |
|---|---|
| 无服务使用 | 断开网络后双击 HTML，画布和编辑功能完整可用，没有外部资源请求 |
| 两层模板 | 画布和节点模板独立；新增节点使用统一结构，内容彼此独立 |
| 节点编辑 | 卡片只读；五组内容可折叠，名称中英两列；新增展开，折叠保留编辑；确定后模型和页面一致，取消及 Esc 不改变原数据，旧内容完整兼容 |
| 参数是否确定 | 尚未填写的输入输出显示待确认；明确没有参数时才显示无参数 |
| 交互不冲突 | 编辑、选择文字、窗口内部滚动不会误拖画布；标题拖动和缩放正确，窗口底部按钮始终可见 |
| 分组 | 加入、移出、移动整组、解散组；归属与位置一致，解散不丢节点 |
| 连线 | 圆点之间拖拽、预览、取消；点击后连线和箭头高亮橙色，无选中方框，中间图标编辑文字或确认删除；双击不编辑，空白或 Esc 取消选中，按钮跟随移动和缩放；保存恢复所选边，旧箭头可继续使用 |
| 来源状态 | 手动修改核对过的接口会标成待核对；纯布局变化不改变来源状态 |
| 覆盖保存 | 修改后保存，原路径文件内容变化，没有自动生成新副本 |
| 再次打开 | 关闭后重新打开已保存 HTML，节点、接口、关系、分组和布局完整还原 |
| 另存为 | 新文件存在、旧文件不变；后续保存写入新目标 |
| 取消与失败 | 取消授权、写入异常、保存期间继续编辑都不会错误显示全部已保存 |
| 特殊文本 | 中文、引号、换行、HTML 标签和脚本结束标签往返保存后不损坏、不执行 |
| 代码分析规则 | 用一个小型真实代码样例检查模块与关系出处；示例中的假想代码不标成已核对 |

自动检查、真实浏览器操作和人工看过页面分别记录。没实测的项目不能报告通过。

## 10. 后续文档阶段
