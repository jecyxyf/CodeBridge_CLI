# CodeBridge_CLI 远程开发与本地硬件联调方案总结

## 1. 核心目标与分工

解决“本地工程包含硬件驱动必须在本地运行，同时需要调用远端 VPS 上的 AI Agent 开发代码并操控网页调试”的问题。

| 节点 | 承担角色 | 具体职责 |
| :--- | :--- | :--- |
| **本机（客户端）** | 硬件运行与代码落盘 | 连接硬件、运行驱动程序、启动前后端服务、保存最终代码 |
| **VPS（服务端）** | AI 开发与网页调试 | 运行 AI Agent（如 `agy`、`claude`、`codex`）修改代码，并通过映射端口打开网页进行自动化操控调试 |
| **连接桥梁** | 同步、穿透与终端 | 1. 终端直连 VPS 操作 Agent<br>2. 本地与 VPS 项目目录双向实时同步<br>3. 本地网页与接口端口反向映射到 VPS |

---

## 2. 核心工具能力边界（`Mutagen` + `ssh`）

采用 **系统自带 `ssh` + 开源工具 `Mutagen`（`mutagen-io/mutagen`）** 一步到位解决全部需求：

| 维度 | 具体说明 |
| :--- | :--- |
| **能做什么** | 1. 跨平台（Windows / macOS / Linux 互通）<br>2. 两边文件夹毫秒级双向实时增量同步<br>3. 把本地 TCP 端口反向挂到 VPS（满足 `IP:端口` 基础内网穿透与远端网页调试）<br>4. 支持 `mutagen.yml` 一键启停全部同步和端口转发 |
| **边界与限制** | 1. 无官方图形界面（纯后台常驻管家，可用 `mutagen sync monitor` 看实时文字状态）<br>2. 不带交互式黑窗口（进服务器敲命令仍直接用系统 `ssh`）<br>3. 仅支持按 `IP:端口` 转发 TCP，不带二级域名分流、访问密码锁与 UDP 穿透 |

---

## 3. `Mutagen` 工作机制与源码模块对应

`Mutagen` 本身不包含独立的 SSH 客户端，而是直接借用本机系统自带的 `ssh` 通道工作：

| 模块 / 程序 | 安装位置 | 作用说明 |
| :--- | :--- | :--- |
| `mutagen` 主程序 + `daemon` | **仅装在本机** | 后台常驻管家，负责监控文件变动、转发端口、关掉窗口不断连、断网自动重连 |
| `mutagen-agent` 小助手 | **自动传到 VPS** | 首次通过 `ssh` 连上 VPS 时由本机自动拷过去，无需在 VPS 手动安装；仅在本机连接期间听指挥干活，断开即停 |
| `sync`（文件同步） | 本机 <-> VPS | 双向实时增量同步指定文件夹；两边都是本地硬盘读写，Agent 搜代码、改代码不卡顿 |
| `forward`（端口转发） | 本机 -> VPS | 将本地网页/接口端口反向映射到 VPS（可仅绑 VPS 本地 `127.0.0.1` 供远端 Agent 浏览器调试，也可绑 `0.0.0.0` 供外部通过 `VPS_IP:端口` 访问） |
| `project`（项目编排） | 本机配置文件 | 通过一份 `mutagen.yml` 一键启动或关闭整套目录同步与端口映射 |

---

## 4. 完整连接与使用流程

| 步骤 | 做什么 | 实现方式 | 最终效果 |
| :--- | :--- | :--- | :--- |
| **第 1 步：打通免密连接** | 配置本机到 VPS 的 `ssh` 公钥 | 标准 `ssh` 免密登录 | 后续同步、转端口、进终端都不用反复输密码 |
| **第 2 步：绑定双胞胎目录** | 建立本地项目目录与 VPS 目录双向同步 | `mutagen sync`（配置忽略 `node_modules`、`.venv`、`dist`、`target` 等依赖和构建大目录） | VPS 上 Agent 改完代码，1 秒内自动同步回本机硬盘 |
| **第 3 步：映射本地网页端口** | 本机带硬件驱动启动服务，把端口反向接到 VPS | `mutagen forward`（如 `user@vps:tcp:localhost:3000` <- `tcp:localhost:3000`） | 远端可直接打开网页并点按操控，硬件在本机正常响应 |
| **第 4 步：打开远端终端** | 进入 VPS 项目目录操作 Agent | 系统 `ssh`（建议搭配 VPS 上的 `tmux` 防断网丢任务） | 在本机终端指挥远端 Agent 改代码 + 调网页，形成完整闭环 |

## 5. 安全边界与硬件联调注意事项

1. **安全隔离边界**
   - 连接方向是**本机单向控制 VPS**，VPS 没有登录本机的权限。
   - **文件隔离**：VPS 只能看到被绑定的那 **1 个项目文件夹**，无法访问本机桌面、其他磁盘或任何其他文件。
   - **端口隔离**：VPS 只能访问明确转发过去的那几个端口，本机其他软件和端口一律不可见。

2. **本地硬件驱动联调必查项**
   - **硬件控制方式**：只要硬件是由**本机启动的后台服务程序**去读写控制（绝大多数工程均如此），远端操控网页就与在本机操作完全一致；仅极少数依赖浏览器直接弹窗连接本地 USB 口（如 WebUSB/WebSerial）的页面无法隔空直连本机硬件。
   - **多端口一并转发**：如果前端网页（如 `3000` 端口）和控制硬件的后台接口（如 `8000` 端口）分属不同端口，且前端没有做统一代理转发，需要把这两个端口同时映射到远端。
   - **前端外部访问配置**：若通过 `VPS公网IP:端口` 在外部访问本地开发服务器（如 Vite），本地启动时需允许外部地址访问（如加 `--host` 参数）。
