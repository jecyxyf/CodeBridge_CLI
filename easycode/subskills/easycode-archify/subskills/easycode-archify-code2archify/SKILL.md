# 源代码转架构数据

## 输入与输出

- 输入：源码目录或明确的文件范围、需要分析的内容，以及可选的现有架构 JSON。
- 输出：符合当前 EasyCode 数据模型的架构 JSON，以及分析范围和核对结果。
- 本技能目录的上两级是技能包根目录；下面提到的命令从包根目录运行。

按需查看 [数据模型](../../tools/html/assets/model.js)，使用其中的字段、创建函数、更新函数和校验规则。

默认架构文件为 tools/archify.json。新建项目先读取 [默认数据模板](../../tools/html/templates/archifytemplate.json)，使用模型创建新的项目 ID，再应用模板默认值并填入实际源码内容；更新已有项目时保留原 ID。

## 工作步骤

1. 阅读目标仓库的协作规则，明确分析边界。用搜索定位定义、调用和引用，再读取相关实现；文件名或搜索命中本身不足以证明模块职责和关系。
2. 有现有 JSON 时，先读取并检查，以它为更新基准，保留用户名称、稳定 ID、布局、外观和分析范围之外的内容。
3. 按实际源码组织模块和分层，记录模块功能、编程语言、相对代码位置、参数、数据结构、方法输入输出、流程、错误处理、事件和测试要求。只记录本次确实核对到的内容，不自动把每个文件或函数都变成模块。
4. 新对象使用 EasyCode.Model.createProject、createModule、createInterface、createParameter、createStructure、createStructureField、createEvent 等创建函数。方法在 JSON 中仍使用 interfaces 字段。用中文名称和说明解释内容；源码中已有的英文标识可记录在 englishName，不随意改名。
5. 关系通过模块 ID 连接，附上确实读取过的出处。相对代码位置与来源行号分别记录。源码版本和工作区状态按实际仓库填写。
6. 无法确定的事实单独说明，不编造类型、调用关系或源码依据。只有经过源码核对的事实才标记 verified；修改现有语义时使用模型更新函数，按规则更新来源状态。
7. 运行 EasyCode.Model.validate(project)。修复结构错误，核查有意义的警告；不要为了消除提示而填入虚假事实。检查通过后写入用户指定的 JSON 文件，再读回比较。

可以从 Node 导入模型，创建函数会注册到 globalThis.EasyCode.Model：

    import './tools/html/assets/model.js';

## 源码核对要点

- Git 项目记录实际版本，并从整个仓库的工作区状态确定 repository.dirty，不能只看分析范围。修改过、未跟踪或忽略的源码在结果说明中记录必要的差异或内容哈希；Git 提交号不足以证明这些文件的实际内容。
- sources 使用便于迁移的仓库相对路径，行号从 1 开始；记录的是实际读到的文件内容。非 Git 目录如实说明，不能编造提交号。
- 模块功能要读实现，方法要核对定义、默认值、分支和返回位置；有向关系要有真实调用或导入依据，不能仅凭同名判断。
- inputsConfirmed、outputsConfirmed 只有在对应输入输出已经核实时才为 true。空列表且未确认表示未知，不能当作已经确定没有参数。
- 重新核对时检查来源行号和版本。只核对部分内容就明确范围，范围外过时的事实不能一并恢复为 verified。
- JSON 或网页生成成功只能证明数据结构及生成过程，不能作为软件实现已经通过验证的依据。

## 交付

报告 JSON 路径、分析的源码范围、模块及关系数量、代码版本和仍未核实的内容。总技能需要继续生成网页时，将通过检查的 JSON 路径交给 archify2html。本技能不修改被分析的软件代码，也不自行生成额外网页或文档。
