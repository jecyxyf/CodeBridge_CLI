# 码桥 CodeBridge 0.0.4

本地目录，远程使用。当前版本是可审查的 MVP / 测试版，不是已完成全部平台验收的正式版本。

- 本地：中文浏览器工作台，类似聊天应用的布局。聊天、模型、Agent、历史会话暂未接入，不会伪造 AI 回复。
- 设置：服务器、SSH 端口、用户名、密码、首次连接信任确认、HTTP CONNECT / SOCKS5 代理、本地共享目录、可选远端挂载目录。
- 诊断：SSH Ping、实际代理隧道测试、挂载阶段状态；连接后自动验证一次读写，并保留手动重测。SSH Ping 是应用层 SSH 可达性检查，不是 ICMP。
- 远端：只部署一个按连接运行的挂载辅助程序和 SSHFS，没有网页、常驻 Agent 或构建系统。
- 本地主动通过 SSH 连接远端；远端目录是本地目录的读写挂载，不是两份工程目录的同步。
- 不使用 Tailscale、frp、密钥登录或配对服务。

0.0.4 在每次远端挂载确认可读后，自动执行一次临时文件读写验证，显示验证进度和结果，并保留“验证读写”按钮。刷新页面不会重复触发；验证失败时保留目录连接，可手动重测。更新后关闭旧客户端，再运行现有启动器即可，无需重装依赖。

日志与超时更新需要同时更新两端：关闭并重启客户端，在服务端重跑对应部署脚本以安装日志模块和结束确认协议。第 6 步现在在后台执行，总时限 20 秒；界面显示远端读写、本地写回、清理和两端确认的进度，超时返回具体阶段错误。

Linux/macOS 服务端首次初始化会在 SSH 用户的家目录下生成一个五位随机小写英文字母目录，并在 `~/.codebridge/server.json` 保存名称，重连沿用。配置损坏时显示警告，保留损坏副本并生成新目录和配置，旧目录不会删除。客户端可填写远端绝对路径或 `~/目录` 覆盖本次挂载位置，留空则使用服务器默认值。此更新还需在远端重跑部署脚本；Windows 远端仍使用自动盘符。

包含 0.0.3 的 Windows rclone 配置路径修复；旧缓存不会被删除或复用。

## 快速开始

获取本仓库 `0.0.4` 分支。已有仓库可运行 `git fetch origin`，再运行 `git switch --track origin/0.0.4`（本地已有该分支时使用 `git switch 0.0.4` 和 `git pull --ff-only`）。关闭旧客户端并重新启动。

Windows 本地客户端，在 PowerShell 中进入仓库目录运行：

```powershell
powershell -NoProfile -File .\local_client\scripts\windows.ps1
```

Linux 远端，在远端仓库目录运行：

```sh
bash remote_server/scripts/linux.sh
```

脚本不启用 SSH 密码登录、不修改防火墙、不开放额外监听端口。服务器应已经提供可用的密码 SSH 登录。不要把客户端密码发送到日志、命令行或仓库。

详细六平台部署、依赖与限制：[部署指南](docs/deployment.md)。

客户端启动器会打开带临时会话令牌的 `127.0.0.1` 页面。设置在用户目录保存，但 SSH 密码从不保存。首次连接不需要填写或记住指纹：客户端会显示服务器地址，点击“信任并连接”后才保存身份并发送密码。首次信任不能独立证明服务器身份；有疑虑时，可展开身份详情并通过可信渠道核对指纹。以后自动比对，身份变化时停止连接，不会自动覆盖记录。服务器管理员可在服务器控制台使用 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256` 查看对应主机公钥指纹。SSH 协商可能选用其他主机密钥类型，须核对实际协商的指纹，而不是盲目复制客户端显示值。

设置中的“删除指纹”只清除当前地址和端口的 CodeBridge 信任记录，不影响其他服务器或系统 SSH 配置。必须先断开，再明确确认删除；下次连接重新询问信任。它不是网络或密码错误的修复方法。

## 架构

```text
本地浏览器（仅 127.0.0.1）
    -> 本地 Python HTTP 控制端（临时令牌、来源检查）
    -> Paramiko：代理 -> SSH 密码认证 + 首次确认后固定服务器身份
    -> SSH exec 二进制通道（无 PTY）
         远端：SSHFS passive/slave -> 真实挂载点
         本地：rclone serve sftp --stdio -> 选择的目录
```

数据通道的 stdout 只承载二进制 SFTP；状态走 SSH stderr。远端确认操作系统真实挂载且目录能够列出后才显示“已连接”，随后自动验证一次读写；只有远端读写、本地写回及临时文件清理均成功，才显示“读写验证通过”。仍可点击“验证读写”手动重测。挂载失败不回退到普通空目录。每次连接使用新的会话 ID；Linux/macOS 的默认目录名称保持不变，断开后保留空目录供重连使用。挂载目录必须为空，不能遮盖已有文件；同一用户已有连接时拒绝抢占。

## 安全与写入边界

请先阅读 [安全和验证边界](docs/security-and-testing.md)。尤其注意：

1. 共享目录是授予远端读写能力，不是对恶意本地程序的 OS 安全沙箱。不要共享系统盘、家目录、密钥、凭据或其他敏感目录。
2. 当前 rclone 固定发行版为 1.75.2，运行时最低要求 1.75.0。禁用跟随/翻译链接、隔离配置并清除 `RCLONE_*` 环境覆盖。
3. 为支持单独写入和随机覆盖操作，rclone 使用本地 VFS 写入缓存。这是 I/O 缓存，不是第二份工程同步，但断电/断线时可能存在未写回数据。不要在仍写入时断开；缓存保留供恢复，当前版本不声称强制断开时零数据丢失。
4. 不支持两端同时编辑同一文件的冲突合并；停止一端编辑后再在另一端操作。
5. 已发现 rclone 1.75.2 对已有本地文件以 `r+`（O_RDWR）句柄读取会返回协议错误。当前验证覆盖分开的读取与保存操作，不能据此宣称所有编辑器、数据库或构建工具兼容。完整 SSHFS O_RDWR 行为仍需实机验证。
6. Linux 完整 FUSE 挂载、Windows/macOS 安装及挂载需要真实操作系统验收，本仓库明确记录未测项。

## Python 运行环境契约

Python 运行环境必须部署在仓库根目录的 `./.venv`。项目运行、依赖安装、测试及 Python 开发工具统一使用该环境的解释器，不能使用系统或全局 Python、仓库外虚拟环境或 Conda 环境替代。客户端部署脚本已使用此路径；开发时也必须遵守，详见 [项目工作指南](AGENTS.md)。

在仓库根目录准备 Python 3.10+ 环境（系统 Python 仅用于探测和创建虚拟环境）：

```sh
python3 -m venv .venv
./.venv/bin/python -m pip install -r local_client/requirements.txt
./.venv/bin/python -m local_client.app
```

Windows PowerShell：

```powershell
py -3 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r .\local_client\requirements.txt
& .\.venv\Scripts\python.exe -m local_client.app
```

以上命令仅准备 Python 环境并启动应用；rclone、Tkinter 等平台依赖仍需按部署指南准备。已有环境不兼容时先检查原因，不要删除或回退到全局 Python；`.venv` 不得提交，也不能跨操作系统复制复用。

## 运行日志与超时

- 客户端：项目根目录 `logs/YYYY-MM-DD.log`。
- 服务端：实际 `mount.py` 所在目录的 `logs/YYYY-MM-DD.log`；部署后为 `~/.codebridge/remote_server/logs/`，Windows 为 `%USERPROFILE%\.codebridge\remote_server\logs\`。
- 路径由程序文件位置确定，不依赖终端当前目录或 Python 解释器位置。按各端本地日期每天一个文件，保留当天及此前 89 天，启动及跨日写入时清理过期日期日志。
- 格式为 `时间,消息类型,日志内容`，支持 `DEBUG`、`INFO`、`WARN`、`ERROR`；包含逗号的内容按 CSV 转义，换行转成字面 `\n`，每条记录占一行。
- 两端用相同的 `session` 标识关联日志，记录步骤、超时和“连接流程运行结束”。成功结束需完成远端读写、本地写回、探针清理及服务端确认；失败也记录结束原因。服务端 helper 在 SSH 认证后启动，前面的客户端操作和 SSH 认证不能由它独立观察。
- SSH 密码、网页会话令牌和完整请求体不写入日志。

```text
2026-10-22 21:30:01.123,INFO,session=示例会话 步骤6运行结束：远端读写、本地写回、清理及服务端结束确认完成
2026-10-22 21:30:01.124,INFO,session=示例会话 连接流程运行结束：成功，六个步骤完成
```

网络连接（含 DNS/代理）、SSH 握手及密码认证分别最多 15 秒；首次人工信任确认最多 120 秒。挂载阶段客户端最多等 45 秒，服务端对准备、真实挂载、目录读取分别设置期限。读写验证共享 20 秒总预算，文件锁最多等待 3 秒；超时不会报告成功，也不会自动重试可能已经发生的写入。普通网页请求最多 10 秒，SSH 诊断和目录选择分别为 35 秒、125 秒。

手动“验证读写”通过 HTTP 202 异步启动，完成结果由状态接口返回。验证失败保留现有连接，可查看两端日志后重测；结果不确定时保留探针文件并提示路径。
